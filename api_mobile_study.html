1. 完整 Request → Response 流程

        
Client ↔ HTTP/HTTPS ↔ Server ↔ Database

        
[前端 Client]
  1. 組裝 Method + URL + Headers (Token) + JSON Body
     │  HTTPS Request
     ▼
[後端 API Server]
  2. CORS / Auth 驗證 (JWT) → 參數檢查 (Validation)
  3. 業務邏輯 → 讀寫 Database / 外部服務
     │  HTTP Status (200/4xx/5xx) + JSON Response
     ▼
[前端 Client]
  4. 檢查 res.ok → 解析 res.json() → 更新 UI 狀態

      


      

        
2. HTTP 狀態碼速記表

        
一眼判斷問題出在誰身上

        
• 2xx 成功：200 OK（查詢/更新成功）、201 Created（新增成功）、204 No Content（刪除成功）。

        
• 4xx 前端/請求端問題：400 參數錯、401 未登入、403 沒權限、404 找不到、429 請求太頻繁。

        
• 5xx 後端伺服器問題：500 程式崩潰、502/503 閘道或服務暫時無法使用、504 逾時。

      


      

        
3. API 除錯三步驟

        
快速釐清前端 vs 後端責任

        
• 1. 開 DevTools Network：確認實際送出的 URL、Method、Headers（有無帶 Token）與 Payload。

        
• 2. 看 Status 與 Response：若出現 CORS error 是後端 Header 沒放行；4xx 查前端參數；5xx 查後端 Log。

        
• 3. 用 curl 獨立重現：在終端機直接打 API，排除瀏覽器快取與前端程式碼干擾。
