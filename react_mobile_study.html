1. React 渲染三階段循環

        
Trigger → Render → Commit → Paint

        
[1. Trigger 觸發]
   初次掛載 / 呼叫 setState()
         │
         ▼
[2. Render 計算]
   執行元件函式 → 產生新 Virtual DOM → Diff 找出差異
         │
         ▼
[3. Commit 提交]
   只把「最小必要變更」寫入真實 DOM
         │
         ▼
[4. Paint & Effect]
   瀏覽器繪製畫面 → 執行 useEffect() 副作用

      


      

        
2. 元件單向資料流原則

        
Props 往下傳・Callback 往上報

        
• 父 → 子：透過 props 傳遞資料與事件回呼函式（唯讀，子元件不可直接改 props）。

        
• 子 → 父：子元件觸發事件時，呼叫父元件傳下來的 onChange / onSubmit 函式通知父層更新 State。

        
• 兄弟共享：將共用 State 提升到最近的共同父元件（Lifting State Up），或跨多層時改用 Context / 狀態管理庫。

      


      

        
3. useEffect 執行時序速記

        
先清舊的 Cleanup，再跑新的 Effect

        
• useEffect(fn, [])：僅在初次掛載執行一次；元件卸載（Unmount）時執行 Cleanup（開發環境 Strict Mode 會額外執行一次 setup 與 cleanup 以檢測副作用）。

        
• useEffect(fn, [id])：id 變動後重新渲染完成 → 先執行上次的 Cleanup（如 abort()）→ 再執行本次 Effect。
